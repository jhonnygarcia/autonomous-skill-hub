# i18n de la UI — plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** que la perilla global de idioma que ya existe gobierne también la UI del
orquestador y los mensajes de error del backend, no sólo lo que escribe el agente.

**Architecture:** dos mecanismos, elegidos por una regla sola —**si la cadena lleva
markup adentro, va al módulo por idioma; si no, va al diccionario**. Un
`strings.ts` con `t(clave)` y `plural(n, uno, varios)` cubre las ~230 cadenas
mecánicas; los 41 bloques de prosa con `<strong>`/`<code>` se indexan por idioma
donde ya viven, sin extraerles las palabras. El idioma se resuelve una vez al
arrancar (cacheado en `localStorage` para que no haya parpadeo) y cambiarlo
recarga la página. En el backend, un `MSG[clave][idioma]` leído con
`setting("idioma")`.

**Tech Stack:** React + TypeScript + Tailwind (`apps/orchestrator/frontend/src/`),
FastAPI + SQLite (`apps/orchestrator/backend/app.py`), pytest, oxlint, tsc.

**Spec:** `docs/superpowers/specs/2026-08-19-idioma-de-los-entregables-design.md`
(secciones 7 y 8, corregidas el 2026-08-19 con la medición por formas)

**Precondición, ya cumplida:** las fases 0-3 del spec están implementadas y en
`main` (12 commits, hasta `ea3fb88`). `GET/PUT /idioma`, `lang()`, `LANGS`,
`MARKERS`, `WORDS`, `w()`, `journal_code()` y el componente `Language.tsx` ya
existen. Este plan **no los rediseña**; los consume.

## Global Constraints

- **Código y comentarios en inglés.** El texto de UI es español o inglés según el
  diccionario. Los comentarios de componente de este repo están en español
  (`Archive.tsx`, `Models.tsx`) y se dejan como están: no es el trabajo de este plan.
- **Literales de contrato, jamás traducidos, en ninguna dirección:** `HUELLA`,
  `SONDEAR`, los valores `ok|parcial|nada`, las claves JSON de la API (`fases`,
  `puntos`, `tipo`, `decidir`, `bloquea`, `estado`, `entregable`), las rutas HTTP
  (`/modelos`, `/idioma`, `/artefacto?ruta=`), y **los estados que devuelve el
  backend** (`queued`, `running`, `analyzed`, `briefed`, `surveyed`, `planned`,
  `implemented`, `error`). Estos últimos son la trampa de la Task 2: hoy se usan
  como claves y como palabras a la vez.
- **Idiomas válidos: exactamente `"es"` y `"en"`.** Default `"es"`.
- **Ninguna dependencia nueva.** Ni `react-i18next`, ni `i18next`, ni
  `Intl.PluralRules`. Dos idiomas de plural simple no lo pagan.
- Frontend: desde `apps/orchestrator/frontend/`, `npm run build` (tsc -b + vite) y
  `npm run lint` (oxlint). **No hay harness de tests de frontend en este repo** —
  build y lint son la única puerta automatizada, y es la convención de la casa, no
  una omisión. No agregues uno.
- Backend: desde `apps/orchestrator/backend/`, `.venv/Scripts/python -m pytest tests/ -v`.
  La suite está en **292 pasando**. Cualquier caída es una regresión.
- **Nunca `uvicorn --reload` en Windows.** Bash en esta máquina no tiene coreutils
  ni git: todo por PowerShell o por las herramientas Read/Edit/Write.
- **Nunca `git push`.** Los commits van directo a `main`, autorizado por el humano.

## Convención de claves del diccionario

Una sola, y se respeta en todas las tareas: **`<archivo-en-minúscula>.<qué-es>`**,
en inglés, descriptiva del rol y no del texto.

    "settings.archive.title"      no  "archivoDeEntregables"
    "ticket.run"                  no  "ejecutar"
    "project.form.repoPathLabel"  no  "rutaDelRepo"

Una clave nombrada por su texto miente en cuanto el texto cambia. Las claves
compartidas por más de un archivo van bajo `common.` (`common.save`,
`common.cancel`, `common.delete`, `common.back`).

**Interfaces:**

- Produces: `type Lang = "es" | "en"`, `lang(): Lang`, `t(key: string): string`, `plural(n: number, one: string, many: string): string`, `initLang(): Promise<void>`. Las cinco las consumen todas las tareas siguientes.

- [ ] **Step 1: Create `strings.ts`**

```ts
/** El idioma de la UI. Vive en la DB (`settings.idioma`, la misma perilla que
 *  gobierna lo que escribe el agente) y se cachea en `localStorage` sólo para
 *  poder pintar el primer frame sin esperar la red. La DB es la fuente de verdad:
 *  si el caché miente, `initLang` lo corrige y recarga. */
export type Lang = "es" | "en"

const KEY = "orq.idioma"
let current: Lang = "es"

export function lang(): Lang {
  return current
}

/** Resuelve el idioma antes del primer render. Arranca con lo cacheado —si no hay
 *  nada, español, que es el default del backend— y consulta la DB después. Sin el
 *  caché, la app pinta un frame en español y salta al inglés a la vista del usuario. */
export async function initLang(): Promise<void> {
  const cached = localStorage.getItem(KEY)
  if (cached === "es" || cached === "en") current = cached
  try {
    const r = await fetch("/api/idioma")
    if (!r.ok) return                       // la DB manda, pero si no contesta el
    const { idioma } = await r.json()       // caché es mejor que nada
    if (idioma === "es" || idioma === "en") {
      current = idioma
      localStorage.setItem(KEY, idioma)
    }
  } catch {
    // sin red no hay nada que corregir: seguimos con el caché
  }
}

const ES: Record<string, string> = {
  "common.save": "Guardar",
  "common.cancel": "Cancelar",
}

const EN: Record<string, string> = {
  "common.save": "Save",
  "common.cancel": "Cancel",
}

/** Una cadena de UI. Una clave que falta se devuelve tal cual, en vez de romper la
 *  pantalla: un texto raro es un bug visible, una pantalla en blanco es una llamada. */
export function t(key: string): string {
  const dict = current === "en" ? EN : ES
  return dict[key] ?? ES[key] ?? key
}

/** Plural para dos idiomas de plural simple. `Intl.PluralRules` es de más acá, y lo
 *  que había antes —pegar el sufijo a mano (`decisión{n > 1 && "es"}`)— no sobrevive
 *  a un idioma donde el plural no es un sufijo del singular. */
export function plural(n: number, one: string, many: string): string {
  return n === 1 ? one : many
}
```

### Task 2: `status.ts` — y la trampa del color

**Files:**

**Esta tarea es chica y es la de mayor riesgo del plan. Leé esto antes de tocar nada.**

`status.ts` tiene hoy dos mapas encadenados:

```ts
const COLOR: Record<string, string> = {
  registrado: "border-border bg-muted text-muted-foreground",
  corriendo: "border-info/60 bg-info/12 text-foreground",
  analizado: "border-success/60 bg-success/12 text-foreground",
  ...
}
const LABEL: Record<string, string> = {
  queued: "registrado", running: "corriendo", analyzed: "analizado", ...
}
```

y el consumidor hace, en efecto:

```ts
const label = LABEL[t.status] ?? t.status
return { label, color: COLOR[label] ?? COLOR.registrado }
```

**`COLOR` está indexado por la palabra española que `LABEL` produce.** Si traducís
`LABEL` y dejás `COLOR` como está, `COLOR["registered"]` es `undefined`, el `??`
se lo traga, y **todos los badges caen al gris de «registrado»**. No falla ningún
build, ningún lint, y nadie se entera hasta que mira la pantalla y los estados se
ven todos iguales. Es el mismo defecto silencioso que en la fase anterior hacía que
un `BLOQUEA` se pintara amarillo.

- [ ] **Step 1: Re-key `COLOR` by the backend state, which is a contract literal**

El estado del backend (`queued`, `running`, `analyzed`, …) no se traduce nunca; la
palabra que ve el humano sí. Así que el color tiene que colgar del estado, no de la
etiqueta:

```ts
// Indexado por el ESTADO del backend, no por la etiqueta que se muestra: la
// etiqueta se traduce y el estado no. Cuando esto colgaba de la etiqueta,
// traducirla dejaba todos los badges en el gris del fallback sin romper nada
// visible para el compilador.
const COLOR: Record<string, string> = {
  queued: "border-border bg-muted text-muted-foreground",
  running: "border-info/60 bg-info/12 text-foreground",
  analyzed: "border-success/60 bg-success/12 text-foreground",
  briefed: ...,
  surveyed: ...,
  planned: ...,
  implemented: ...,
  error: ...,
}
```

Copiá el valor de cada clase Tailwind **verbatim** del mapa actual, emparejando por
el par que hoy forman `LABEL` y `COLOR`. No inventes ni «mejores» ningún color.
El fallback pasa a ser `COLOR.queued`.

- [ ] **Step 3: Prove nothing was missed, with a command**

Guardá este script como `apps/orchestrator/frontend/i18n-check.ps1` — lo van a
usar también las tareas 4 y 7, y deja de ser un chequeo de una vez para ser el
gate del trabajo:

```powershell
# Cuenta lineas con texto español visible fuera de comentarios. ASCII-only:
# Windows PowerShell 5.1 lee los .ps1 como ANSI y mastica los acentos del fuente.
param([string]$Root = "$PSScriptRoot\src", [string[]]$Only = @())
$L = 'a-zA-Z\u00e1\u00e9\u00ed\u00f3\u00fa\u00f1\u00c1\u00c9\u00cd\u00d3\u00da\u00d1'
$words = @('el','la','los','las','un','una','de','del','que','para','con','sin','por',
           'no','se','es','son','hay','cada','todo','todos','esta','este','su','sus',
           'al','lo','pero','como','cuando','donde','desde','hasta','entre','sobre',
           'corrida','corridas','fase','fases','proyecto','ticket','tickets','rama',
           'repo','repos','nada','guardar','cancelar','borrar','ejecutar','continuar',
           'responder','aceptar','abrir','nuevo','nueva','editar','volver','idioma',
           'entregable','decisiones','archivo','ajustes','modelo','motor','esfuerzo')
$re = '(?i)(^|[^' + $L + '])(' + ($words -join '|') + ')($|[^' + $L + '])'
$accent = '[\u00e1\u00e9\u00ed\u00f3\u00fa\u00f1\u00c1\u00c9\u00cd\u00d3\u00da\u00d1\u00bf\u00a1]'
$total = 0
foreach ($f in Get-ChildItem $Root -Recurse -Include *.tsx, *.ts) {
    if ($Only.Count -and $Only -notcontains $f.Name) { continue }
    if ($f.Name -eq 'strings.ts') { continue }   # el diccionario ES vive ahi a proposito
    $inBlock = $false; $n = 0
    foreach ($ln in (Get-Content $f.FullName -Encoding UTF8)) {
        if ($inBlock) { if ($ln -match '\*/') { $inBlock = $false }; continue }
        if ($ln -match '^\s*/\*') { if ($ln -notmatch '\*/') { $inBlock = $true }; continue }
        if ($ln -match '^\s*(//|\*)') { continue }
        if ($ln -notmatch '["''`>]') { continue }
        $s = [regex]::Replace($ln, 'className=(\{?"[^"]*"\}?|\{`[^`]*`\})', '')
        $s = [regex]::Replace($s, '(from|import)\s+["''][^"'']+["'']', '')
        if ($s -match $re -or $s -match $accent) { $n++ }
    }
    if ($n) { "{0,-20} {1,3}" -f $f.Name, $n; $total += $n }
}
"TOTAL: $total"
```

```python
# UI-facing: lo lee el humano en el navegador. Sigue la perilla, como `WORDS`, pero
# a diferencia de `WORDS` esto no termina dentro de ningún `.md` del repo destino —
# es una respuesta HTTP y se resuelve siempre contra la perilla, nunca contra un
# archivo. Los `code` estructurados (ver `RESTORE_EXISTS_CODE`) son contrato con el
# frontend y NO viven acá: sólo el `msg` que los acompaña.
MSG = {
    "es": {
        "no_es_directorio": "No es un directorio: {d}",
        ...
    },
    "en": {
        "no_es_directorio": "Not a directory: {d}",
        ...
    },
}


def msg(key: str, **fmt) -> str:
    return MSG[lang()][key].format(**fmt)
```

Las claves en inglés y descriptivas del error, no del texto. Cada clave existe en
**las dos** mitades: una que falte es un `KeyError` en un handler.

- [ ] **Step 5: Convert the 49 call sites**
